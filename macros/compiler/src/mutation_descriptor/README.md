# `mutation_descriptor` — generated mutation discovery declarations

This home reads one declaration's mutation-policy helper and renders the producer facts `TestPak` lowers into an executable evaluation surface.

The author states the evaluation family, the mapping from sealed generated facts to owner claims, the operator families each claim permits, and the mechanical address of the generated output.
The producer discovers point identities, activation sites, unchanged operation bytes, and adjacent alternatives from the refusal declaration it already captured.

The refusal-family frontend constructs one complete `MutationProjectionRequest`, including the actual production order expression and destination-shaped typed rows, before it calls this mechanical renderer.
This is a review-enforced module seam: `mutation_descriptor` imports no refusal-family frontend type or rendering helper.

The helper is an independent reading of the declaration and therefore has its own commitment.
It is absent from the production semantic commitment; the generated-support carrier composes it with any trial commitment only where the two deliveries meet.

The output remains data until `TestPak`'s closed lowering admits it.
An owner-unmapped or mapped-but-unpermitted discovery remains in the complete reading and cannot become executable, and this home neither mints active directives nor judges mutation evidence.

The physical vehicle is the existing generated-support carrier, its evaluation cargo, its deferred module, and its schema gate.
Production reads the owner declaration's actual `DECLARED_ORDER`, an evaluation with no active mutation delegates to production, and an active adjacent selection returns only its separately rendered alternative.
This home declares no projection kind, cargo axis, gate seat, proc-macro door, compiler host, selector state, or copied original order.
