# Native coverage controls

These controls compose the public compiler and coverage entrances with actual installed rustc and matching LLVM tools.
The existing compiler test owner supplies explicit host configuration; subject bytes and expected novelty/refusal outcomes are authored independently here.
Task-created subjects remain disposable under the ordinary target and are reconstructed from tracked source.
The Cargo crossing compiles a decoder through the renamed registry 0.2.0 facade while exercising the current source's native host.
Independent literal count bytes and an expected read-back distinguish successful decoding from truncated input.
The generated decoder's selective call into caller assembly supplies novelty, and the actual registry macro location remains mapped.
This does not claim that stable line coverage distinguishes every generated branch.
Hostile tool stand-ins independently exercise phase-specific deadline, output, exit and missing-tool failures; they never establish positive LLVM coverage.
Presentation controls read those same executions in JSON, Markdown and HTML, preserving exact candidate bytes, novelty order, tool/target declarations, every reached failure plane and pending cleanup without performing effects.
