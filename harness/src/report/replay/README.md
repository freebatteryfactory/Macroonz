# replay — a saved witness against a current report

This home compares an owned historical capsule with an independently earned current trial report.
It reads values and performs no execution, decoding, reduction or admission to a replay depot.
The [runner](../../runner/README.md#saved-witness-replay) owns the operation that earns the current report.

## The witness join

Comparison requires the exact retained witness bytes in an admitted input envelope and the envelope's complete profile and case in the current report.
A report with unit input, another specimen or another input convention cannot stand in for that execution.
The original historical case belongs to the execution from which reduction began; it need not equal the reached witness's fresh case.
Lineage records whether those cases agree, differ under the same convention, cannot be compared because the convention moved, or lack historical input standing.

## Outcome and movement

The outcome and coordinate movement are separate readings.
A defect is reproduced when the current execution refuses under the historical semantic trial and fingerprint on the joined witness.
That observation alone does not assert unchanged source, exact execution equivalence or authentic historical custody.

Fixed-on-witness requires a passing current execution, a changed subject revision, the same semantic trial, and unchanged check revision, input profile, schema, decoder revision and posture, target, toolchain and invocation budgets.
Both historical and current executable standing must be at least declared.
This is a bounded comparison relative to the historical claims, not proof of a global repair or an authenticated history.
A pass without that standing remains a pass in its complete current report and is classified as non-reproduction without repair standing.
A different trial, different fingerprint or attempt that did not conclude also remains explicit.

Every comparison retains trial, subject, check, profile, schema, decoder, target, toolchain and budget movement independently of its outcome.
The original and current records retain the actual coordinates; this reading never invents a current key from historical digest claims.

## Historical standing

Historical input absence and untracked executable standing remain separate reasons that historical reproduction cannot be verified.
Otherwise the reading carries the weaker of the historical claimed ceiling and the current earned ceiling.
Even an exact-derived ceiling does not establish unchanged execution when coordinates moved, and no ceiling authenticates the historical author.
The current report preserves its own conclusion, finding, source site and measurement regardless of that historical limitation.

## Sparse legacy claims

`compare_legacy` requires the same exact witness, profile and case join for a bounded `LegacyRecord`.
It accounts for every supported historical field, preserving missing, null and uninterpreted values.
A missing or null profile parent remains distinct from an omitted or null leaf inside a present object.
Only target and toolchain spellings, the execution digest claim, and an available refusal fingerprint claim are compared to current coordinates.
An absent current fingerprint remains unavailable rather than different or equal.
Opaque numeric revisions, free-form names, profile fragments, header labels, witness data and outcome prose do not acquire current identity or conclusion meaning.

The historical standing is always unverifiable because the sparse record lacks complete execution and fingerprint preimages.
Even matching claims cannot establish reproduction or repair, and the runner's complete current report remains independently inspectable.
