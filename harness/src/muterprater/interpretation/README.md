# interpretation

Interpretation owns production and evaluation call types and bindings, observations, evaluation pairs and their standing, mutation witnesses, no-mutation results and parity, interpreted trust and availability, interpreted mutation evidence, execution refusals, and the substrate names those values require.

The private noun home and the public verb are distinct: this home defines no public `muterprater::interpretation` ontology.
Its values remain on the existing `muterprater::*` surface, while `muterprater::interpret` is the narrow public operation over them.

## Dependencies

Interpretation consumes discovery's surfaces, directives, selections, and refusal vocabulary through the parent `muterprater` paths.
It consumes backend suite pressure and verdict evidence through those same parent paths, and consumes specimen's compiled projection pressure without absorbing specimen custody or host semantics.
Specimen in turn reads interpretation's pair standing, witness, and no-mutation qualification, so the two homes form a reference cycle while retaining separate semantic ownership.
Trial bindings and reports remain owned by `runner` and `report`, and equivalence and substrate vocabulary remain owned by `properties`.

## Nonclaims

A function pointer remains a caller statement, and interpretation records only the values, firings, reports, and joins its typed operations observe.
Generic suite pressure, compiled projection pressure, and interpreted activation remain distinct evidence routes.
No interpretation value discovers a mutation, invokes a compiler host, or changes verdict or backend semantics.
