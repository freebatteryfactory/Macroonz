# External economics subject

This material exercises the public compiler, generated Rust and adopter compilation in separately launched native processes.
It is canonical test material, not a product module, benchmark backend, or another registered Cargo package.
For compiler and runtime execution, the manual qualification host selects optimized library artifacts and supplies source, compiler and target identities.
No product library reads the host clock or launches this process.

`compiler-axes.rs` owns compiler workloads, independent structural expectations and declared work judgments.
Each measured call constructs and compiles its input again and consumes the resulting Rust or exact refusal.
`runtime-pilot.rs` owns generated dispatch, relation-table and codec consumers; `runtime-shapes.rs` supplies growing recipe structures and independent arithmetic/byte expectations.
Its call-count and structure-width axes remain separate, and its timed codec interval includes allocation and drop rather than claiming isolated codec instructions.
`measurement.rs` binds compiler and runtime declarations to the existing public harness benchmark receiver and supplies an external monotonic clock.
Identical work must fail the planted-worse gate; doubled actual execution must satisfy the declared work distinction before timing begins.
`resident.rs` holds the consumed bytes until the external observer supplies the exact release token and EOF.
A readiness line without a successful process exit does not establish a completed observation.
`memory-control.rs` supplies the external allocation-sensitivity and failed-child/deadline controls; it measures no Macroonz behavior itself.
`build-adopter.rs` supplies the independently consumed recipe for an external Cargo build observation.
`build-control.rs` supplies output-bound, failed-child, timeout and inherited-stream controls for that observation's external process host.
That observation uses a disposable standalone adopter manifest with a declared dependency graph and development profile, not the optimized-artifact execution road.
Its declared transition target is the only edited source seat; the separate executable argument selects the handwritten expectation over the complete two-state domain and the effect count.
The build-report crossing requires all cold, unchanged, edited and unchanged-after-edit observations, successful consumers, reconciled artifact freshness, stable lock and clock scale, and unchanged executable bytes within each no-op pair.
It reads a compact projection of native observations, not Cargo JSON itself; the host must retain and reconcile the native process records before producing that projection.

The qualification host owns process and output bounds, native memory observation, source custody and report reconciliation.
Raw records remain disposable under its exact target.
Timing includes the declared whole callable interval, and native maximum RSS includes the whole child process rather than only compiler heap allocation.
Repeated samples expose variation; neither their existence nor a work-qualified report establishes a performance threshold, source-version improvement or asymptotic complexity.
