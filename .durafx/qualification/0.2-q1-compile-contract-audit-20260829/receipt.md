## Genuine owner boundary

The repository does not yet define what exact compiler-diagnostic identity means.

- The narrow contract is exactly one stable error code plus exactly one normalized primary span, with ambiguity refused.
- The broad contract is a diagnostic roster retaining multiplicity, secondary spans, code-less diagnostics, or some combination of them.

The current external holder establishes only the narrow shape under one `E0308` control.
The bank silently chooses that shape without earning it as the repository's general compatibility contract.
The choice changes public constructors, ambiguity refusals, comparison cardinality, canonical bytes, identity, and future compatibility.
No concrete public name or signature is authorized until the owner rules on this boundary.
