## Owner ruling

The full wishlist behavior remains required while its implementation must first compose from existing Macroonz batteries.

For generalized compiler-refusal contracts, one authoritative diagnostic anchor consists of:

- one stable rustc error code;
- one normalized primary source span mapped relative to the declared challenge root.

The anchor is the comparison and compatibility material.
It does not claim that rustc emitted only one diagnostic overall.
Notes, secondary spans, unrelated diagnostics, rendered prose, and other structured compiler output may remain bounded human evidence but do not enter comparison, canonical identity, or compatibility law.

The extraction road must establish exactly one relevant primary anchor without silently selecting the first.
Zero or multiple relevant anchors must produce a typed inability to establish the observation rather than a pass or an invented subject verdict.
A changed code at the same span and a changed span under the same code remain independent disagreements.

- The existing runner and report rails retain package invocation standing, target, toolchain, not-run, infrastructure, and checked trial admission.

## Future-compatible posture

Future Macroonz self-hosting is outside the 0.2 lot but constrains this design against a dead end.

- Handwritten and generated callers must use the same public contract.
- The diagnostic anchor must not depend on macro generation or an absolute scratch path.
- Its deterministic framing must remain suitable for ordinary generated Rust declarations.
- A future bounded diagnostic roster may compose these atoms additively if independent subject pressure earns that behavior.
- The 0.2 implementation must not name or document the single anchor as the complete compiler-output model.
