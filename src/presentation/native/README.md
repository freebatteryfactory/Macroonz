# native — displayed native observations

This home reads the opt-in [compiler](../../native_compiler/README.md), [mutation](../../native_mutation/README.md) and [process](../../native_process/README.md) owners without starting, waiting for or cleaning a child.
`storage_error` reads the [storage owner's](../../native_storage/README.md) refusal without touching files or inferring a transaction's current state.
Run and benchmark retention refusals preserve their distinct storage, input, archive and join causes; neither overwrites a subject conclusion or guesses which shared read/write operation was invoked.
`stored_run` reads the [workflow owner's](../../workflow/README.md) already-admitted historical join, retaining original input, the complete report and every stored capsule at its original census position.
The stored report and reached witnesses retain historical standing, and displaying them performs no readback, decoding, reduction or replay.
Compiler output retains its declared invocation, interpreted observation or interpretation failure, reported executable, Cargo freshness and separately established dependency roster or refusal.
Pending compilation displays unfinished cleanup and establishes no compilation observation.
Compiler startup, interpretation, read-back and semantic comparison remain separate phases under their existing owners.
The [publication projection](publication/README.md) composes those observations with complete output inventories, formatting, destination discrepancies and command cleanup custody.

Mutation output retains both version-query outputs, its declared request and original source bytes, and the established manifest and grammar qualification or their observation refusal.
Preparation failures preserve their typed cause and any version-query phase, command and finished or pending process.
Pending mutation displays unfinished cleanup without interpreting output or reading current sources.
Source currency and historical retention remain separate operations owned by native mutation and its harness backend.

Process output retains the stop condition, native exit status and each pipe's exact retained prefix and independent capture end.
Coverage readiness retains the original request and established source map beside the explicit native tool and target process limits.
Its preflight and observation failures retain the responsible operation, owning refusal or process error, and any case directory or cleanup error still owned by the failure.
Reading a pending coverage failure does not finish cleanup, release its candidate file or admit novelty.
Unlike bounded harness foreign text, a pipe prefix is not capped again for display, and an unknown total byte count is not invented.
Native paths retain `OsStr::as_encoded_bytes` alongside Unicode or lossy display text; these platform-dependent bytes are display evidence, not a portable path encoding.
Exit status includes the standard-library code and display text, plus the platform's raw wait status on Unix.
Command arguments and the explicitly supplied environment are displayed in full.
Presentation therefore exposes the supplied record's contents to its reader; it neither chooses an environment nor reads one.
